4. Confirmed Architectural Guardrails

1. Core owns generic TASK identity, assignment and lifecycle.
2. Marketplace owns request-and-quotation selection.
3. Business Modules retain service-specific data and rules.
4. Winning quotation, Core assignment and competing quotation closure must not leave partial or contradictory states.
5. Profile-origin requests use the same quotation workflow as marketplace-origin requests.
6. Preserve existing migration history and release records.
7. Do not introduce a fixed-price engine unless separately approved.
8. Do not remove the Pick & Drop internal TASK without evidence and approved design.
9. Do not treat previous CI results as proof that a newer commit passes.
10. Do not start implementation while Batch 0 remains unapproved.

5. Outstanding Design and Audit Gaps

- Define the relationship and ownership boundaries among Business Module request, Marketplace request, quotation and Core TASK.
- Define the transaction boundary for quotation acceptance, Core assignment and competing quotation closure.
- Define idempotency and recovery behaviour for retries or partial failures.
- Confirm the effect of runner suspension on existing quotations and assignments.
- Define public runner profile fields, stable URL, privacy protections and unavailable-runner behaviour.
- Define request-source attribution and analytics.
