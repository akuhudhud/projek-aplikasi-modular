3. Confirmed Architectural Guardrails

1. Core remains the owner of generic TASK identity, assignment and lifecycle.
2. Marketplace owns the request-and-quotation selection process.
3. Business Modules retain service-specific data and rules.
4. A winning quotation, Core assignment and closure of competing quotations must not leave partial or contradictory states.
5. Profile-origin requests must use the same quotation workflow as marketplace-origin requests.
6. Existing migrations and released history must remain intact.
7. Do not introduce a fixed-price engine unless separately approved.
8. Do not remove the existing Pick & Drop internal TASK until dependency and regression analysis justifies a change.
9. Do not treat documentation or a previous release's CI result as proof that the current HEAD passes.
10. Do not begin implementation while Batch 0 remains unapproved.
